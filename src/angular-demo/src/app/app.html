AuthKit for Angular — demo

Para programadores que integram autenticação numa aplicação Angular e querem ver os componentes a correr contra um host real: a mesma UI ligada a dois providers — Supabase (e-mail, magic link, recuperação, OAuth) e Cl@ve (federação eIDAS iniciada pelo servidor). Tudo servido pelo host de demonstração em {{ origin }}, na mesma origem, sem CORS.

  • Angular 22
  • standalone
  • @authkit/angular 0.1.0
  • zoneless

Cl@ve (eIDAS)

O browser só constrói o URL do host e lê o resultado do redirect. A asserção SAML, a validação e a sessão ficam no servidor — o SDK nunca recebe um token Cl@ve.

Descritores reais

Cada botão emite o URL e o handler chama window.location.assign(url), tal como a produção faria. O nível escolhido entra como loa; o método, como method.

@if (lastNavigation()) {

Último URL: {{ lastNavigation() }}

}

O que acontece a seguir

  1. GET {{ claveLoginPath() }}?loa=…&method=…&returnUrl=/angular/ inicia a federação no host.
  2. O host redireciona para a pasarela local (stub assinado) e recebe a asserção no ACS.
  3. O host valida, cria o cookie e devolve o utilizador a /angular/.
  4. Esta página volta a ler GET /session e mostra a identidade no topo.

Falhas: o host deste demo redireciona para / com ?error=… (FailurePath), não para /angular/.
